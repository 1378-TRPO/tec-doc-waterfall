# SRS v1.0 - «Календарик»

## 1. Назначение и scope

«Календарик» - веб-календарь для маленькой компании (пародия на Google Calendar). Планировщик: события, встречи с участниками, внешние ссылки на созвон, in-app уведомления, RSVP. **Не** сервис видеозвонков, **не** интеграция с Google/Yandex API.

## 2. Функциональные требования (FR)

- **FR-1:** регистрация и вход по email и паролю; неверный пароль - сообщение об ошибке. Для MVP мокирования авторизация (пул фикстур пользователей)
- **FR-2:** авторизованный пользователь видит календарь на [выбранный промежуток] с записями.
- **FR-3:** создание «события»: название, описание, начало события, конец события.
- **FR-4:** создание «встречи»: те же поля + внешняя ссылка + участники из списка пользователей.
- **FR-5:** валидация: название не пустое, конец позже начала, ссылка начинается с `http://` или `https://`.
- **FR-6:** участник видит встречу и может принять/отклонить (RSVP).
- **FR-7:** организатор видит RSVP-статусы участников в карточке встречи.
- **FR-8:** организатор может «пингнуть» участника -> in-app уведомление.
- **FR-9:** уведомления типов `invited / pinged / changed / cancelled`; колокольчик с числом непрочитанных; страница уведомлений; отметка прочитанным.
- **FR-10:** панель «Ближайшие встречи» - будущие записи, где я организатор или участник, по времени.
- **FR-11:** кнопка «Сгенерировать демо-ссылку» -> `https://meet.local/<random>`.
- **FR-12:** редактирование и отмена встречи организатором.
- **FR-13:** данные в PostgreSQL, переживают перезапуск.

## 3. Нефункциональные требования (NFR)

- Backend: C# / .NET 10, ASP.NET Core Web API, EF Core.
- Frontend: React 19 + TypeScript 6, Vite 8, React Router 7 + TanStack Query 5, Axios 1, TablerIcon.
- БД: PostgreSQL 16.
- Auth: JWT или cookie, пароли хэшируются (`BCrypt.Net`).
- Запуск: `docker compose up -d db`, `dotnet run`, `npm run dev`.
- Отклик на действие - до 1 секунды.
- README с запуском и известными ограничениями.

## 4. Acceptance criteria

- Вход seed-пользователем работает; неверный пароль -> ошибка.
- Создание встречи на завтра 10:00–11:00 с участником и ссылкой -> встреча видна в календаре.
- Пустое название / конец раньше начала / кривая ссылка -> ошибка, запись не создана.
- Участник принял RSVP -> организатор видит `accepted` в карточке.
- Пинг участника -> у участника появляется непрочитанное уведомление.
- Уведомление можно отметить прочитанным.
- Перезапуск приложения -> встречи, RSVP и уведомления на месте.
- Ссылка на встречу кликабельная.

## 5. Вне scope (out of scope)

- Email / push / telegram / WebSocket уведомления.
- Интеграция с Google / Yandex Calendar API.
- Свой сервис видеозвонков.
- Повторяющиеся события, часовые пояса.
- Приглашение внешних (не зарегистрированных) пользователей.
- Приватные календари и шаринг.
- Drag-and-drop в календаре.
- Cron / напоминания по расписанию.
- Мобильная верстка.
- Автотесты UI.

## 6. Глоссарий

- **Событие** - личная запись в календаре без участников.
- **Встреча** - запись с участниками и внешней ссылкой на созвон.
- **Пинг** - напоминание участнику внутри приложения.
- **RSVP** - ответ участника на приглашение: pending / accepted / declined.
