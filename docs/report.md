# Отчёт — «Календарик»

## 1. Общие сведения

- **Продукт:** «Календарик» — веб-календарь для маленькой компании.
- **Цель:** собрать MVP по методологии Waterfall и продемонстрировать работу на паре.
- **Команда:** 5 человек (роли в `docs/00-team-charter.md`).
- **Тимлид / PM:** Виноградов Андрей.
- **Репозиторий:** `tec-doc-waterfall`.

## 2. Этапы Waterfall

| Этап | Артефакт | Статус |
|---|---|---|
| Инициация | Team Charter | `docs/00-team-charter.md` |

## 3. Scope продукта

MVP включает:
- регистрацию и вход (FR-1);
- календарь на месяц (FR-2);
- события и встречи с участниками (FR-3, FR-4);
- валидацию полей (FR-5);
- RSVP и статусы участников (FR-6, FR-7);
- in-app пинги и уведомления (FR-8, FR-9);
- панель «Ближайшие встречи» (FR-10);
- генератор демо-ссылок (FR-11);
- редактирование/отмену встречи (FR-12);
- хранение данных в PostgreSQL (FR-13).

За scope отвечает SRS v1.0; изменения фиксируются в `docs/05-change-log.md`.

## 4. Архитектура (кратко)

- Backend: C# / .NET 8, ASP.NET Core Web API, EF Core, Npgsql.
- Frontend: React 18 + TypeScript, Vite, React Router, axios.
- БД: PostgreSQL 16.
- Auth: JWT/cookie + BCrypt для паролей.
- Календарь: FullCalendar (react-обёртка).

Подробное описание архитектуры и решений — в `docs/02-design-doc.md`.

## 5. Результаты

- Реализованы все FR-1…FR-13 в рамках MVP.
- Код проходит сборку (`dotnet build`, `npm run build`).
- Ручные тест-кейсы из `docs/03-test-plan.md` выполнены (подробности — в `docs/04-test-report.md`).
- Демо проведено по `docs/demo-script.md` за 5 минут.

## 6. Использованные подходы к тестированию

- Ручное функциональное тестирование по тест-плану.
- Проверки по технике «чёрный ящик» — через UI.
- Проверки по технике «белый ящик» — просмотр логики валидации и статусов на backend.
- Unit-тесты для критичных сервисов backend (опционально, по решению команды).

## 7. Внедрение и поддержка

- Запуск локально: `docker compose up -d db`, `dotnet run`, `npm run dev`.
- Подробная инструкция — в `docs/06-deployment.md`.
- Поддержка: исправление критичных багов, обновление seed-данных, ведение Change Log — `docs/07-support.md`.

## 8. Выводы

Проект показал, как команда может пройти полный цикл Waterfall: от фиксации требований до демо готового MVP. Основной упор сделан на процесс, артефакты и согласование scope, а не на объём функциональности.
