# Demo Script — «Календарик»

**Длительность:** 5 минут  
**Роли на демо:** спикер (PM или frontend-разработчик), второй голос (Design Doc owner / backend).

## Подготовка

1. Запущены: PostgreSQL (`docker compose up -d db`), backend (`dotnet run`) и frontend (`npm run dev`).
2. В БД есть минимум два seed-пользователя, например `alice@local` и `bob@local`.
3. Открыты два браузера/вкладки: один пользователь — органайзер, второй — участник.

## Сценарий

### 1. Вход (30 сек)

- Спикер открывает приложение, вводит логин и пароль seed-пользователя.
- Показывает: вход выполнен, открывается календарь на месяц.
- Для контраста: вводит неверный пароль → появляется сообщение об ошибке (FR-1).

### 2. Создание встречи (90 сек)

- Органайзер нажимает «Создать встречу».
- Заполняет: название, описание, завтра 10:00–11:00, внешняя ссылка, выбирает участника из списка.
- Сохраняет — встреча появляется в календаре (FR-2, FR-3, FR-4).
- Кратко показывает валидацию: пустое название / конец раньше начала / ссылка без `http*` → ошибка (FR-5).

### 3. RSVP участника (60 сек)

- Переключаемся на вкладку участника.
- Участник видит встречу и нажимает «Принять».
- Возвращаемся к органайзеру, открываем карточку встречи — статус участника `accepted` (FR-6, FR-7).

### 4. Пинг и уведомление (60 сек)

- Органайзер в карточке встречи нажимает «Пингнуть» участника (FR-8).
- На вкладке участника у колокольчика появляется «1 непрочитанное».
- Участник открывает страницу уведомлений и отмечает пинг прочитанным (FR-9).

### 5. Ближайшие встречи и демо-ссылка (30 сек)

- Органайзер открывает панель «Ближайшие встречи» — только что созданная встреча в списке (FR-10).
- Нажимает «Сгенерировать демо-ссылку» → получает `https://meet.local/<random>` (FR-11).

### 6. Финал (30 сек)

- Спикер кратко: «Все данные хранятся в PostgreSQL, переживают перезапуск» (FR-13).
- Второй голос добавляет: «Редактирование и отмена есть у органайзера, out of scope — настоящие видеозвонки, Google API, push-уведомления» (FR-12, раздел 5 SRS).

## Запасной план

Если на демо что-то пойдёт не так:
- Заранее подготовить скриншоты/запись успешного прохождения.
- Показывать только главный happy path: вход → создать встречу → RSVP → пинг.
